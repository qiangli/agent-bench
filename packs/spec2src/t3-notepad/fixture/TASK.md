Build the `notepad` app described by CONTRACT.md, SKILL.md, features.yaml and examples/ in this directory. Deliver source and an executable POSIX-sh launcher `./notepad` at the workspace root. `./notepad` is run on Linux x86_64 with Go 1.27, Python 3.12, Node 18, sh, curl and jq, with loopback networking only. `bashy` is on the PATH there for one purpose, the converter that the contract's Venue section names (`bashy lens`); use nothing else of bashy. Dependencies must be standard library only or vendored here. Your work is judged by its behaviour: the contract's commands, the service rules and the page it serves. The judge's tool is on your PATH: `conform run CONTRACT.md --dir . --path . --fresh-home` runs every assertion in CONTRACT.md against your `./notepad` and prints PASS or FAIL for each. Use it while you build. The assertions start a server on the fixed loopback address the contract names and stop it at the end; leave no server running when you finish.

dag.md in this directory is the app's lifecycle and is part of the spec. Do not change it. Make each of its steps work when its code block is run with `sh` from this directory on the same Linux machine: `build` (you supply `build.sh`), `test`, `install`, `run`, `serve` and `stop` (you supply the `serve` and `stop` commands of `./notepad`; CONTRACT.md has the service rules). A lifecycle test runs those steps in order on a fresh copy of your work and checks that the service answers after `serve` and no longer answers after `stop`.
